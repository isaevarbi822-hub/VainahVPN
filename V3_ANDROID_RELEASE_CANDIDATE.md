## Specific audited fixes in this chain

- Reject duplicate/ambiguous OAuth callback parameters.
- Bound server TCP scans and display **TCP** measurements as such.
- Provide coherent violet server cards and LTE category across screens.
- Never present Android physical-network validation as verified VPN egress.
- Bound native cabinet refresh waiting by a common deadline.
- Ignore corrupt TCP probe observations with impossible sample counts.
- Parse valid server tariff rows even if neighbors are malformed; discard invalid rows
  without reserving plan IDs or trusting alternate checkout links.

## Safe smoke-test checklist for an Android preview APK

1. Install the **isolated debug APK** generated by the PR's Android workflow.
   Keep production signing keys and real billing out of the preview.
2. Open home, server list, security, diagnostics, account, theme settings.
   Check dark/light mode, keyboard focus, scrolling and small-screen rendering.
3. Import an authorized subscription. Verify no raw VLESS URI or auth token
   appears in screenshots, log messages, or exported diagnostics.
4. Test selection/search/favorites/LTE without claiming a node's label verifies access.
5. Start VPN. Test browser connectivity and external IP independently; then move
   Wi-Fi→mobile data→Wi-Fi, check no misleading green/online status after failure.
6. Enable Android **Always-on VPN** and **Block connections without VPN** if the
   device and VPN role permit it; inspect IPv4/IPv6/DNS behavior. The UI cannot
   enable system lockdown by itself.
7. Verify email OTP, Google and Telegram sign-in with provider configuration.
   Inspect account, device limits, support threads and renewal reminders.
8. Confirm free trial eligibility via authenticated server status; do **not**
   repeatedly claim trials or trigger test payments against live customers.
9. Browse plans; confirm the native UI only opens a verified official checkout URL.
   Real charges and automated H1Cloud fulfilment require separately authorized E2E tests.
10. Confirm Android and Python CI **success** for this exact candidate SHA
    before distributing an APK.

## Release safeguards

- The repository's `main` branch is not presently the integration baseline for
  the running Android/backend feature code. Do not blindly merge or deploy to main.
- These branches do not change live RollyPay settings, subscription balances,
  user accounts, H1Cloud nodes or production deployments.
- Passing CI does **not** establish functional VPN protection or provider login.
- Open PRs #79–#85 remain for historical review; one consolidated PR compares
  this release candidate against the Android 3.0 feature baseline.
