# Vainah VPN Next — состояние новой архитектуры

## Реализовано в новой ветке

- Перенесена проверенная база Android/Gradle, VLESS + REALITY и libbox из
  предыдущего проекта (исходная версия: октябрь 2026).
- Старый монолитный `MainActivity.kt` заменён небольшим Android-экраном:
  подключение/отключение, список локаций, кабинет и диагностика.
- `SubscriptionController.kt` отдельно управляет запросами, устаревшими
  ответами, Keystore-кэшем и безопасной передачей результатов в UI.
- Android `VpnService` остаётся владельцем туннеля. Только его реальный
  статус отображается на главном экране.
- Прямые `vless://` ключи и HTTPS-подписки поддерживаются существующим
  проверяемым парсером; UI не печатает секреты.
- Удалены неиспользуемые Android-модули `NativeIdentity` и
  `NativeCheckout`, которые всё ещё обращались к старому Netlify.
- Новое приложение имеет другой application ID:
  `app.vainah.vpn.next` (debug: `app.vainah.vpn.next.preview`).
- Покупки/платежи принудительно выключены.

## Чего ещё нельзя утверждать

- Автоматическая сборка не доказывает, что сторонний сервер подписки
  устранит HTTP 403. Для этого нужны правила доступа/логи сервера.
- Libbox ранее работал на реальном Android, но именно **новая** версия
  не считается проверенной, пока не подтверждены VPN-подключение,
  маршрутизация внешнего IP, DNS, IPv6, смена Wi-Fi/сотовой сети.
- Clerk в новой сборке работает только после настройки реального
  publishable key в GitHub Actions. Секретный ключ нельзя класть в APK.
- Python/Render API, оплата, iOS и Windows пока не перенесены в этот
  репозиторий и не являются готовыми функциями новой версии.

## Сборка Android

Для разработчиков с Android SDK и Gradle 8.11.1:

```bash
gradle -p android -PvainahEnableLibbox=true -PvainahIsolatedPreview=true :app:assembleDebug :app:testDebugUnitTest
```

GitHub Actions: `.github/workflows/android.yml`.

APK — **debug-предпросмотр для безопасного тестирования**. Не отключайте
защитные функции телефона ради его установки. Публичный релиз потребует
доверенной подписи и полноценного тестирования.

## Отдельная проверка HTTP 403

1. На том же Android и в той же сети убедиться, что Happ действительно
   **обновляет** ту же подписку, а не только использует старый кэш.
2. Сравнить только безопасные признаки запроса: HTTP-код, тип ответа,
   требования к авторизации, User-Agent, правила привязки устройств.
3. Не добавлять чужой HWID и не обходить проверку TLS/ограничения доступа.
4. При временном отказе показывать **последние ранее загруженные** серверы
   как кэш, не заявляя, что они доступны или подписка действительна.

Исходный `Vainahvpn_bot` не изменён этой миграцией.
