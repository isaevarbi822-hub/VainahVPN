# Vainah VPN — восстановленный сайт и RollyPay

## Откуда взят дизайн

Полный публичный сайт восстановлен из старого репозитория
`Vainahvpn_bot`, ветка `feature/rollypay-isolated-sandbox-20261024`
(главная, тарифы, поддержка, инструкции, устройства, вспомогательные страницы).
Оригинальные стили сохранены в `storefront/`.

Новый сервер:
- `/` — прежняя главная.
- `/plans.html` — прежние тарифы.
- `/checkout.html` — новая страница оформления в прежнем стиле.
- `/app` — отдельный кабинет Vainah Next (preview).
- `/api/shop/plans` — тарифы (единственный источник цен).
- `/api/shop/config` — состояние оплаты без секретов.
- `/api/shop/checkout` — **503**, пока нет безопасной авторизации и выдачи.
- `/api/shop/sandbox/start` — приватный тестовый заказ (операторский токен).
- `/api/shop/sandbox/{order_id}` — приватный тестовый статус.
- `/api/shop/sandbox/{order_id}/simulate` — демонстрация, без денег (mock).
- `/api/shop/webhooks/rollypay` — проверка подписи тестового вебхука.

## Что означают результаты тестов

CI проверяет, что страницы/локальные ссылки существуют, CSS/JS не ломают сборку,
цены нельзя подменить через клиент, платёжная ссылка разрешена только на
`pay.rollypay.io`, а вебхук требует подпись по оригинальным байтам:
HMAC-SHA256(`X-Timestamp + "." + raw_body`) и временное окно 5 минут.

**Тесты кода ≠ подтверждение работы реального счёта**, и sandbox
`paid` не означает, что реальная подписка оплачена или выдана.

## Тестирование без денег

По умолчанию `VAINAH_SHOP_SANDBOX_MODE=mock`, никакие запросы к RollyPay
не отправляются. Для локальных проверок в окружении (не в GitHub!):

```dotenv
VAINAH_SHOP_SANDBOX_ENABLED=enabled
VAINAH_SANDBOX_TEST_TOKEN=<сильный уникальный секрет минимум 24 символа>
VAINAH_SHOP_SANDBOX_MODE=mock
```

Оператор вводит `VAINAH_SANDBOX_TEST_TOKEN` на странице checkout,
раскрыв блок тестирования. Симуляция **не списывает деньги**.

Для проверки с реальной кассой, **только с разрешённым мерчантом**:

```dotenv
VAINAH_SHOP_SANDBOX_MODE=provider
VAINAH_SHOP_PROVIDER_TEST_ENABLED=enabled
ROLLYPAY_API_KEY=<секрет кассы>
ROLLYPAY_SIGNING_SECRET=<секрет подписи>
```

В запросе на RollyPay принудительно `"test": true`.
Используются `X-API-Key` и новый `X-Nonce` на каждый запрос.
`callback_url` настроить на HTTPS адрес
`https://<сайт>/api/shop/webhooks/rollypay`.
Проверяется `X-Signature` (HMAC-SHA256) и `X-Timestamp`,
отклоняется любой продакшен-вебхук, неподходящий платёж или сумма.

Все шесть тарифов перенесены без изменений: 99/160/219/339/700/1000 RUB.

## Почему реальная оплата ещё закрыта

В новой ветке нет всех обязательных элементов продакшена:

1. Подтверждённая авторизация покупателя (email/Telegram), защищённые сессии и права.
2. Постоянная база заказов с уникальностью/идемпотентностью, а не память Python.
3. Аудит и подтверждённая касса мерчанта с разрешением на приём платежей.
4. Надёжная выдача/продление подписок H1Cloud, обработка отмен и возвратов.
5. Живые сквозные тесты от создания заказа до получения VPN и проверки срока.
6. Верифицированная настройка деплоя, домена и сертификата HTTPS.

Не задавайте `test:false` в этой версии и **не снимайте
блокировку** `/api/shop/checkout` без всех пунктов выше.
Не храните ни секретные токены, ни ссылки VPN-подписок в публичном GitHub.

Документация RollyPay:
https://docs.rollypay.io/api/payments/
https://docs.rollypay.io/api/callbacks/
https://docs.rollypay.io/api/authentication/

## Python/Render: защищённая проверка Clerk и H1Cloud (read-only)

Веб-сайт остаётся в режиме **preview**. Добавлена **серверная проверка**
Clerk JWT через открытый PEM-ключ и ограничение `iss`/`azp`/`exp`/`nbf`.
Это основа авторизации, **не готовая форма входа**. Личный кабинет пока
не выдаёт персональные данные, реальные покупки и VPN-ссылки.

Настройки для **Render → Environment** (секреты не в GitHub):

- `VAINAH_CLERK_ISSUER` — точный HTTPS issuer из Clerk, как в токене `iss`.
- `VAINAH_CLERK_JWT_PUBLIC_KEY` (или `CLERK_JWT_KEY`) — **публичный**
  PEM-ключ проверки подписи из Clerk (не `CLERK_SECRET_KEY`).
- `VAINAH_CLERK_AUTHORIZED_PARTIES` — доверенные HTTPS origins, например
  `https://vainahvpn-python-preview.onrender.com`. При наличии собственного
  домена перечислить два origins через запятую.

Проверки: `GET /api/auth/config` только сообщает, есть ли конфигурация,
`GET /api/auth/me` принимает исключительно `Authorization: Bearer <JWT>`.
Подписанные, но истёкшие или полученные с другого origin токены отклоняются.
Никакие ключи, сессии и полные JWT наружу не возвращаются.

H1Cloud — перенос **ранее подтверждённого контрактом старого проекта**
read-only запроса `GET /api/clients/{name}` с заголовком Bearer.
Параметры в Render:

- `PANEL_BASE_URL` — только HTTPS-адрес своей панели, без путей кроме
  `/` или `/api`, например `https://vpn-panel.example.com/api`.
- `PANEL_API_TOKEN` — секрет для панели с минимально необходимыми правами.
- `PANEL_CLIENT_PREFIX` — префикс клиентов, по умолчанию `tg`.

Публичное `GET /api/site/services` показывает только наличие настройки,
а не обещает, что панель доступна. Проверить её фактический ответ можно
через `GET /api/site/integrations/h1cloud/check`, **только**
с операторским заголовком `X-Sandbox-Token`. Используется фиктивный
идентификатор без создания клиента. Проверка не возвращает никаких
подписок, VLESS URL, UUID или данных пользователей. При ошибке — только
классифицированный результат без тела ответа провайдера.

**Ничего не активирует реальных пользователей автоматически.** Для запуска
нужно связать проверенный Vainah ID с реальным владельцем подписки,
включить безопасные серверные сессии, подтвердить учёт заказов и
идемпотентную выдачу/продление. До этого live checkout остаётся HTTP 503.


## Telegram Login и подтверждённая почта на Render

Чтобы включить официальный Telegram Login Widget в Render → Environment,
укажи `TELEGRAM_BOT_TOKEN` (из BotFather), `SESSION_SIGNING_KEY`
(случайный секрет от 32 символов), `TELEGRAM_BOT_USERNAME` (публичный
username, по умолчанию `VainahVPNbot`) и `PUBLIC_SITE_ORIGIN`:
`https://vainahvpn-python-preview.onrender.com`. В BotFather командой
`/setdomain` для этого бота разреши `vainahvpn-python-preview.onrender.com`.
Никогда не публикуй токен бота или ключ сессий в GitHub.

`GET /api/telegram/config` сообщает только о готовности, не раскрывая токен.
`POST /api/telegram/account` проверяет подпись Telegram и выдаёт
HttpOnly Secure SameSite=Lax cookie, `GET /api/telegram/account` возвращает
проверенный профиль. Чужие ID и неподписанные данные отвергаются.

Подтверждение почты для вошедшего пользователя требует `DATABASE_URL`,
`RESEND_API_KEY` и `VAINAH_EMAIL_FROM` (email отправителя с подтверждённым
доменом у почтового провайдера). `POST /api/account/email/request` отправляет
шестизначный код и сохраняет только HMAC, а
`POST /api/account/email/confirm` сохраняет подтверждённую почту.
Код действует 10 минут, ограничены частота запросов и число ошибок.

`GET /api/account/overview` показывает только собственный статус,
подтверждённую почту и оплаченные/выданные заказы. Подписка
`GET /api/account/access` выдаётся только владельцу подтверждённого
оплаченного и доставленного заказа и активного профиля H1Cloud.
Таблица заказов не заполняется через публичные маршруты. Внутренний
`notify_confirmed_subscription` отправит собственную VPN-ссылку на
подтверждённый email, **только** после того, как доверенная система
подтвердила оплату и выдачу в H1Cloud. Автоматическое проведение живых
платежей и выдача пока не внедрены и не включены.


## Email login — independently verified passwordless accounts

Email-авторизация теперь отдельная от Telegram. Существующие `RESEND_API_KEY`,
`VAINAH_EMAIL_FROM`, `DATABASE_URL` и `SESSION_SIGNING_KEY` должны быть
заданы в Render; новые ключи специально для входа не нужны. Отправитель
Resend должен иметь право отправлять письма на адреса пользователей.

- `GET /api/email-auth/config` — признаки готовности без секретов.
- `POST /api/email-auth/request` — отправка 6-значного кода на email через
  Resend; код живёт 10 минут. Частота ограничена по почте и источнику.
- `POST /api/email-auth/verify` — проверка кода, его однократное погашение,
  создание подтверждённой email-учётной записи и выдача HttpOnly/Secure cookie.
- `GET /api/email-auth/account`, `POST /api/email-auth/logout` — проверка
  сессии и выход. Отправка и проверка кода требуют правильный Origin.

**Разграничение подписок:** подтверждённый email без Telegram-привязки
получает собственный пустой кабинет, без чужих ключей. Если этот адрес
ранее подтверждён владельцем через Telegram, данные берутся только из
проверенной `vainah_verified_customer_emails` связки. Само по себе
совпадение введённого username / Telegram ID не даёт доступа. Настоящие
покупки и автоматическая выдача по email ещё отключены.


## Проверка реального API без создания заказов

`GET /api/site/services` теперь выполняет кешируемые (180 секунд)
**только GET**-проверки: H1Cloud `/api/clients/tg999999999999999999`
и RollyPay `/api/v1/payments?environment=sandbox`. HTTP-ошибки и
несовпадение ответа переводятся в безопасные статусы без токенов, чужих
платежей или ключей. Это не создаёт покупок, VPN-пользователей и даже не
означает, что подписка будет выдана.

`ROLLYPAY_SIGNING_SECRET` в ответе показывается только как факт наличия
настройки подписи вебхука, без раскрытия значения. Реальная доставка
callback из кассы и создание/продление клиента H1Cloud остаются отключены,
пока не появятся проверенный производственный платёжный журнал, право
пользователя на подписку и схема идемпотентной выдачи.
