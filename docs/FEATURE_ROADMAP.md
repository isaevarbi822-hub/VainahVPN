# Vainah VPN — этапы развития экосистемы

Этот файл отличает **реализованное** от **требующего API, тестов и ресурсов**.
Нельзя отмечать функцию рабочей лишь потому, что добавлена кнопка.

## Сейчас реализовано в коде

1. Подписки, подтверждённая оплата RollyPay и выдача H1Cloud — сохраняем
   текущий production-контракт и не меняем платёжную логику в новых модулях.
2. Email-код + Google OpenID Connect + Telegram OpenID Connect — код с
   серверной проверкой; для двух OAuth-провайдеров нужны реальные client keys
   и allowed redirect URI. См. `docs/OAUTH_SETUP.md`.
3. Подписчик: история покупок, трафик при доступности H1Cloud,
   безопасная CSV-выгрузка и календарное напоминание.
4. Приватный QR-код оплаченной подписки по требованию.
5. Vainah Connect: интерактивные инструкции для Android, iOS/iPadOS,
   Windows, macOS и Linux без ложных утверждений о VPN-туннеле.
6. Новый центр поддержки: заявки и ответы в PostgreSQL. Нужна настройка
   `VAINAH_SUPPORT_OPERATOR_KEY`. См. `docs/SUPPORT_SETUP.md`.
7. Монитор HTTP-отклика сайта, браузерная диагностика и мастера устранения
   проблем. Эти проверки **не измеряют качество самого VPN-туннеля**.

## Следующие функции и необходимые условия

### Серверы и устройства
- Умный выбор сервера: read-only список от H1Cloud с реальными состоянием,
  задержкой и нагрузкой. Не показывать выдуманные ping или онлайн-статус.
- Реальное управление устройствами: проверить, какие операции доступны
  через H1Cloud. Идентификаторы устройств должны подтверждаться сервером.
  Отключение устройства — только с авторизацией, журналом и защитой от гонок.

### Нативные приложения
- Kill Switch: системные API Android `VpnService`, macOS/iOS Network
  Extension и платформенно-зависимая политика Windows. При обрыве
  не допускать трафик вне туннеля. Требует интеграционных испытаний.
- Split Tunneling: правила исключения отдельных приложений в нативных
  клиентах, совместимость с libbox, права и проверка утечек.
- Переключение Wi-Fi/сотовой сети, уведомления о статусе и безопасное
  восстановление соединения. Не реализовывать веб-кнопками.

### Коммерция
- Подарочные коды: только после модели владения, сроков, однократного
  погашения, блокировки злоупотреблений и интеграции с **подписанными**
  RollyPay webhook. Код не должен обходить проверку оплаты.
- Рефералы и бонусы: прозрачный журнал начислений, запрет
  самоприглашений и двойных бонусов, ограничения/условия возвратов.
  Не начислять бонус до реальной подтверждённой покупки.
- Reward-баллы: отдельный ledger с идемпотентностью, проверкой
  возврата и финальным балансом — не просто число в браузере.

### Уведомления и поддержка
- Уведомление об истечении подписки и трафике только по
  серверной подтверждённой дате и счётчику, с добровольным согласием.
- Почтовые ответы поддержки: шаблоны, unsubscribe/предпочтения,
  защита от повторных отправок, безопасность вложений.
- Публичный status: только реальные read-only проверки; не выдавать
  отсутствие данных за нормальную работу VPN.

## Условия выхода в production

- Тесты на отсутствие доступа к чужим заказам, QR и обращениям.
- Проверка cookie, CSRF, CSP, лимитов API и кэширования.
- E2E в реальном браузере на мобильном и ПК.
- Проверка оплаты/выдачи без создания лишних реальных заказов.
- Успешные GitHub Actions и подтверждённый Live Deploy Render.
