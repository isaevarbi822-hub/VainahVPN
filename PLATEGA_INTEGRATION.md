# Vainah VPN — вторая касса Platega

Основная касса RollyPay сохраняется без изменений. Platega — отдельный выбор на `/checkout.html`.

## Render: Python web service

Настройки добавляются **только** в `vainahvpn-python-preview`, не в статический сайт и не в GitHub.

- `PLATEGA_MERCHANT_ID` — реальный UUID магазина, выданный Platega.
- `PLATEGA_SECRET` — реальный X-Secret; вместо него поддерживается `PLATEGA_API_KEY` или `PLATEGA_X_SECRET`. Никогда не храните API-ключ на клиенте.
- `PLATEGA_PAYMENT_METHOD` — целое значение: `2` (СБП) или `11` (карты), если этот метод включён менеджером Platega. При отсутствии используется `2`.
- `PLATEGA_ENABLED=enabled` — разрешить платежи после полной настройки.
- `PLATEGA_WEBHOOK_CONFIRMED=enabled` — устанавливать **только после проверки реального URL callback в настройках Platega**. Это отдельный предохранитель от оплат без доставки.

Существующие боевые проверки Vainah VPN (одобренная касса, доступность авторизации и PostgreSQL, проверенный H1Cloud, работающая выдача) не отключаются. Их не нужно подменять.

## Настройка в Platega

В настройках магазина Platega укажите Callback URL:

`https://vainahvpn-python-preview.onrender.com/api/shop/webhooks/platega`

Это адрес API в Render, **не** адрес статического сайта. Он принимает только POST, ограничивает размер запроса, проверяет заголовки X-MerchantId и X-Secret и дополнительно запрашивает статус транзакции у Platega. Проверяются UUID, сумма, валюта и исходный ID заказа.

После успешной регистрации URL укажите `PLATEGA_WEBHOOK_CONFIRMED=enabled` в Render и дождитесь успешного деплоя. Пока флаг отсутствует, кнопка Platega заблокирована, даже если API-ключ добавлен.

## Проверка без денег

1. `GET /api/shop/config` должен вернуть `platega_ready: true` после полной настройки, либо `false` с заблокированной кассой.
2. Зайдите в личный кабинет и убедитесь, что можно выбрать только включённые кассы.
3. Проверьте, что повторная попытка оформления использует сохранённый intent, а не создаёт новый платёж.
4. Проверьте журнал тестов GitHub Actions и доступность backend. Не создавайте реальный счёт без готового webhook.

**Важное ограничение:** автоматические тесты замоканы — они не проверяют действительные ключи Platega, зачисление денег, настройки аккаунта у провайдера или реальную оплату. Для полного запуска нужен отдельный разрешённый провайдером end-to-end тест.

## Архитектура

Платёжная сумма фиксируется на сервере и в PostgreSQL, а заказ получает неизменяемое поле `gateway`. Подтверждение Platega отправляется через `/api/shop/webhooks/platega`; скрипт обязательно проверяет платёж независимым запросом `GET /transaction/{id}`. Если подтверждённый платёж совпадает с заказом, используется прежний `fulfill_paid_order_once` (атомарная единственная выдача в H1Cloud) и `send_paid_access_receipt_once`.

Потеря ответа на создание платежа не вызывает повторного автоматического POST. Сомнительные выдачи после сбоев или споров остаются на ручную проверку, вместо повторной выдачи.
