# XHTTP/XMUX and TCP/REALITY compatibility fix

The Android baseline is `fix/android-libbox-validation-diagnostics-20261116`
at `a49f54d`, which includes the Android 3.0 feature branch. `main` contains
only the initial README and is not the application integration branch.

The reported `xhttp_xmux_invalid` is a local profile rejection code. The supplied
API 37 diagnostic has VPN off, unknown transport/security and no native startup
failure, so it does not establish an Android 17 platform defect or reveal the
two servers' exact XMUX settings.

The converter rejected forms supported by the pinned sing-box-lx 1.14.4-lx.35:
empty strings, whitespace around ranges, one-element arrays and null XMUX
sections. It also truncated fractional numbers during validation and used only
the second array endpoint to detect conflicting active limits. The correction
normalizes valid ranges, preserves the difference between unset and explicit
zero, and rejects fractions, overflow and conflicting limits consistently.

Only the selected transport's settings are validated. Unused XHTTP query fields
no longer block TCP/REALITY, TCP Vision or gRPC profiles. Actual XHTTP still
requires the native XHTTP core and retains its wire parameters; there is no
transport fallback or relaxation of TLS certificate checks.

Native reference: [XMUX range decoder](https://github.com/Leadaxe/sing-box-lx/blob/f1bac271853eaf13398ce1030c948aebc3aed2e1/option/v2ray_xhttp_xmux_range.go)
and [XMUX defaults and validation](https://github.com/Leadaxe/sing-box-lx/blob/f1bac271853eaf13398ce1030c948aebc3aed2e1/transport/v2rayxhttp/xmux.go).

Build with JDK 17, Gradle 8.11.1, Android SDK 35 and the checksum-verified AAR
from `.github/workflows/android.yml`:

```sh
VAINAH_SYNTHETIC_CONFIG_DIR=/tmp/vainah-native-configs gradle -p android \
  -PvainahEnableLibbox=true -PvainahUseXhttpCore=true \
  -PvainahIsolatedPreview=true \
  :app:assembleDebug :app:testDebugUnitTest --no-daemon
```

The tests export 30 invented configurations for `sing-box check`, including
TLS/XHTTP, REALITY/XHTTP, gRPC, TCP and raw/Vision. They do not contain real
subscription credentials and do not contact production VPN servers.

Validation completed on 2026-11-17: all 273 JVM tests passed (none skipped),
all 30 exported configurations passed the pinned native core's schema check,
and `assembleDebug` succeeded. The APK is `3.0.0-alpha.2-preview` (code 301,
`app.vainah.vpn.next.preview`), with libbox and XHTTP enabled. APK signature
verification and 16 KB ZIP alignment passed; the ARM64 native library also
has 16 KB ELF segment alignment.

This is a debug-signed preview, not a production-signed release. Android can
install it as an update only if the existing preview has the same signing
certificate. Preserve subscription access before replacing a preview signed
with another key.

Device acceptance remains: import the authorized subscription on Android 17,
connect each Turkey server, confirm HTTPS and the external IP, and test a
Wi-Fi/mobile-data transition. Build/schema checks cannot establish live server
reachability or VPN egress. No backend or Render deployment is part of this fix.
